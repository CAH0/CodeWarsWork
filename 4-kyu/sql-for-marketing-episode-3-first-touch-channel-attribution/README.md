<h2><a href=https://www.codewars.com/kata/6871597746901ef70c7bf8d8/train/sql target="_blank">SQL for Marketing – Episode 3: First-Touch Channel Attribution</a></h2><h3>4 kyu</h3><p>A company is conducting multi-channel marketing campaigns through email, SMS, and push notifications. Each campaign involves sending messages to users via one or more channels, and users may engage by opening, clicking, or converting through any of them.</p><p>To evaluate campaign performance, the business team has requested a first-touch attribution analysis. Specifically, they want to determine which channel should receive credit for conversions in cases where a user received multiple messages through different channels.</p><p>The attribution rule is as follows:</p><ul><li>If a user received multiple sends for the same campaign across different channels, any resulting engagement should be attributed to the channel through which the user engaged first. </li><li>Only engagements that happened after the corresponding message was sent should be considered valid. </li><li>Conversions must be analyzed based on this attribution.</li></ul><p>We have <code>campaign_sends</code> table: </p><ul><li><code>id</code> (int): primary key</li><li><code>user_id</code> (int): recipient</li><li><code>sent_at</code>    (timestamp): when the message left </li><li><code>campaign_id</code>    (varchar):    Marketing campaign identifier</li><li><code>channel</code>    (varchar):    'email', 'sms', or 'push'</li></ul><p>and <code>engagement_events</code> table:</p><ul><li><code>id</code> (int): primary key</li><li><code>send_id</code>    (int):    Foreign key referencing <code>campaign_sends(id)</code>. Identifies the exact message the user engaged with.</li><li><code>user_id</code> (int):     ID of the user who performed the engagement.</li><li><code>event_time</code> (timestamp): when the engagement happened</li><li><code>campaign_id</code>    (varchar): Denormalized copy of the campaign identifier that was already stored in <code>campaign_sends</code>. Keeping it here makes ad-hoc queries and CSV exports self-contained: analysts can <code>WHERE campaign_id = 'SUMMER2025'</code> without an extra join, and the raw event row remains readable by itself.</li><li><code>channel</code>    (varchar): Denormalized channel value ('email', 'sms', 'push') for readability and query simplicity. Although this duplicates information from <code>campaign_sends</code>, it allows analysts to filter and aggregate engagement data by channel without requiring a join. It must always match the channel of the referenced <code>send_id</code>.</li><li><code>event_type</code> (varchar):    Type of engagement: 'open', 'click', 'converted' etc.</li></ul><p>Your query must:</p><ol><li>Locate the first engagement:<ul><li>For every distinct (user_id, campaign_id) pair, find the earliest engagement event recorded in engagement_events.</li></ul></li><li>Assign the “first-touch” channel:<ul><li>All subsequent conversion events for that same user + campaign are credited to this first-touch channel.</li></ul></li><li>Return one row per canonical channel, even when there is no data, with the following columns:<ol><li><code>channel</code> (varchar): The name of the channel that received first-touch attribution. Values include 'email', 'sms', or 'push'.</li><li><code>conversions</code> (integer): Count of events where event_type = 'converted' that are attributed to this channel under the first-touch rule.</li><li><code>total_sends</code> (integer): The number of messages sent via this channel for the same campaign ('SUMMER2025') under analysis.</li><li><code>cr_pct</code> (varchar) - Conversion Rate Persentace: Represents the conversion efficiency of this channel. It is calculated by taking the number of conversions attributed to the channel and expressing it as a percentage of the total number of messages sent via that channel. The value should be rounded to two decimal places.</li><li><code>share_of_covs</code> (varchar) - Share of Total Conversions: Indicates how much this channel contributed to the overall pool of attributed conversions across all channels. It should be calculated as the percentage of total conversions that were attributed to this specific channel. The value should be rounded to two decimal places.</li></ol></li></ol><h4 id="notes">Notes:</h4><ul><li>The final result must be sorted using the following multi-level ordering logic:<ol><li>Descending by <code>conversions</code></li><li>Descending by <code>total_sends</code></li><li>Ascending by <code>channel</code></li></ol></li><li>Empty-data behaviour:  The query must return one row for every canonical channel (email, push, sms) even when no messages or conversions exist for that channel (or for the campaign as a whole). In such cases the numeric columns should be 0 and the percentage columns 0.00.    </li><li>Unlike funnel stage analysis (<a href="https://www.codewars.com/kata/686f7daab952c6058e61d70c" data-turbolinks="false" target="_blank">SQL for Marketing – Episode 2</a>) where each engagement must follow a defined sequence (e.g., open --&gt; click --&gt; convert), this task does NOT enforce such a model. A conversion event (<code>event_type</code> = 'converted') may occur without a prior open or click, and this is considered valid behavior.      </li><li>Only include rows for campaign 'SUMMER2025' in all calculations.</li><li>Data is consistent: every engagement in DB is recorded at or after its send. No need to bother about events BEFORE send</li><li>Only conversion events (event_type = 'converted') should be counted in <code>conversions</code> and <code>share_of_convs</code>.</li><li>Tie-breaker for first touch: If two or more valid engagements for the same user &amp; campaign occur at exactly the same timestamp, credit the channel that comes first in alphabetical order (email --&gt; push --&gt; sms).</li></ul><p>For this sample data:</p><pre><code>campaign_sends: | id | user_id | sent_at             | campaign_id  | 2025-07-01 14:10:00 | SUMMER2025   | push   | click       || 3  |    1    |   101   | 2025-07-01 16:00:00 | SUMMER2025   | email  | converted   || 4  |    5    |   102   | 2025-07-02 10:30:00 |
