<h2><a href=https://www.codewars.com/kata/64d499812df37400210180e4/train/sql target="_blank"> Six Consecutive 'No' Outcomes in Customer Calls</a></h2><h3>5 kyu</h3><p>We're analyzing data for a customer support center for a tech company. The "No" outcomes represent failed attempts by companies automated voice assistant to understand customer requests.</p><p>Now, if the voice assistant fails to understand the same customer six times in a row, a live support agent takes over the call.</p><p>Table Schema (<code>calls</code>):</p><ul><li><code>call_id</code> (integer) - The unique identifier for each call.</li><li><code>user_id</code> (integer) - The unique identifier for the customer.</li><li><code>outcome</code> (varchar) - The outcome of the voice assistant's attempt to understand the customer's request. Can be either 'Yes' (understood) or 'No' (not understood).</li><li><code>date_of_call</code> (timestamp) - The date and time when the call occurred.</li></ul><p>Your task is to write a PostgreSQL query to find instances where the voice assistant failed to understand the same customer six times in a row. The result should include the details of the sixth consecutive "No" call.</p><p>The result set should include <code>user_id</code> (integer) and <code>date_of_call</code> (text) columns and be sorted by <code>user_id</code> and <code>date_of_call</code> in ascending order. </p><p>GLHF!</p><p>Notes:</p><ol><li><p>It is guaranteed that each call for user has unique timestamp and in ascending chronological order.</p></li><li><p>If a user has 12 consecutive "No" outcomes, the query should only return the 6th "No," not both the 6th and 12th.</p></li><li><p>If a user has two separate series of 6 consecutive "No" outcomes, each separated by a different outcome, both occurrences of the 6th "No" should be returned.</p></li></ol><h3 id="desired-output">Desired Output</h3><p>The desired output should look like this:</p><table><tbody><tr><th>user_id</th><th>date_of_call</th></tr><tr><td>1</td><td>2022-01-01 00:50:00</td></tr><tr><td>1</td><td>2022-01-01 02:00:00</td></tr><tr><td>2</td><td>2022-01-01 01:20:00</td></tr></tbody></table>...
