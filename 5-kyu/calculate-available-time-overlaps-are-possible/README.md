<h2><a href=https://www.codewars.com/kata/64bcfea1aaff1a6962182f3b/train/sql target="_blank">Calculate Available Time (overlaps are possible)</a></h2><h3>5 kyu</h3><p>In the online tutoring platform, tutors set their availability by specifying a start and end time for each slot. These slots, spanning from 1970 to 2999, can overlap. Your task is to write a performant PostgreSQL query that calculates the total availability time for a specific tutor (e.g., user_id= 777) over their entire record. The query should efficiently handle a large dataset, merging overlapping intervals to compute the total distinct availability in minutes.</p><p>The <code>availability</code> table in your PostgreSQL database has the following schema:</p><ul><li><code>id</code> (integer) - The unique identifier for each availability entry.</li><li><code>user_id</code> (integer) - The unique identifier for the user (tutor).</li><li><code>avail_start</code> (timestamp) - The start time of the availability slot.</li><li><code>avail_end</code> (timestamp) - The end time of the availability slot.</li></ul><p>Write a PostgreSQL query that calculates the total availability time for the user with <code>user_id</code>= 777. The total availability time should be the sum of the durations of all distinct (non-overlapping) availability slots. The result should be given in minutes as a column <code>total_minutes</code> of integer type. The overlapping intervals should be merged. For example, if there is one interval from 16:00 to 17:00 and another from 16:30 to 17:30, the total availability should be considered as 90 minutes, not 120.</p><p>Let's provide a concrete example:</p><pre><code>| id | user_id | avail_start         | avail_end           |+----+---------+---------------------+---------------------+| 1  | 777     | 2023-07-24 16:00:00 | 2023-07-24 17:00:00 || 2  | 777     | 2023-07-24 16:00:00 | 2023-07-24 16:50:00 || 3  | 777     | 2023-07-24 18:00:00 | 2023-07-24 18:30:00 || 4  | 777     | 2023-07-24 17:30:00 | 2023-07-24 18:10:00 || 5  | 777     | 2023-07-24 16:00:00 | 2023-07-24 17:10:00 || 6  | 777     | 2023-07-24 16:00:00 | 2023-07-24 16:50:00 |</code></pre><p>The result should be:</p><pre><code>| total_minutes |+---------------+| 130           |</code></pre><p>Here is the breakdown:</p><ul><li>'2023-07-24 16:00' to '2023-07-24 17:00' (id=1) contributes 60 minutes.</li><li>'2023-07-24 16:00' to '2023-07-24 16:50' (id=2) falls within id=1, so it contributes 0 minutes.</li><li>'2023-07-24 18:00' to '2023-07-24 18:30' (id=3) is a completely distinct interval, so it contributes 30 minutes.</li><li>'2023-07-24 17:30' to '2023-07-24 18:10' (id=4) overlaps 10 minutes with id=3 (18:00 to 18:10), so the unique time contribution of this interval is from 17:30 to 18:00, which is 30 minutes.</li><li>'2023-07-24 16:00' to '2023-07-24 17:10' (id=5) overlaps completely with id=1 but extends 10 minutes beyond it, so it contributes 10 minutes.</li><li>'2023-07-24 16:00' to '2023-07-24 16:50' (id=6) falls within id=1, so it contributes 0 minutes.</li></ul><p>Adding these up: 60 + 0 + 30 + 30 + 10 + 0 equals 130 minutes.</p><p>GLHF!</p><p>Notes:</p><ul><li>It is ensured that the start time is always before the end time</li><li>It is possible that slots start in one day and end in another</li></ul>
